架構介紹

本專案採用 Retrieval‑Augmented Generation (RAG) 與 Large Language Model (LLM) 結合的方式，分為以下兩大部分：

RAG 部分

  • config.py – 讀取環境變數，設定向量資料夾、Embedding 模型、Top‑K、Fetch‑K 等。
  • embeddings.py – HuggingFace Embeddings 包裝 (BAAI/bge-m3)。
  • vectorstores.py – 載入本地 FAISS 向量庫。
  • retriever.py – MultiStoreRetriever，負責相似度搜尋並回傳 top‑k 結果。
  • vector_store_dept/ – 知識來源 (chunks.txt) 與已建好的 FAISS index (index.faiss, index.pkl)。

LLM 部分

  • llm/ollama.py – 與本地 Ollama API (/api/generate) 互動的 LLM 包裝 (ChatOllamaLLM)。
  • orchestrator.py – RAG 與 LLM 的橋梁：retrieve_only() 取得上下文；ask() 將問題與檢索結果送給 LLM。
  • service.py – 對外介面 ChatService.handle：相關性檢查、呼叫 orchestrator、計時、OpenCC 簡體→繁體、組裝最終回覆。
  • relevance.py – 簡單詞彙重疊相關性判斷 (閾值 30%).
  • prompts.py – (保留) Prompt 模板，未來可擴充。

資料流程：使用者問題 → Service → Relevance 檢查 → Orchestrator.retrieve_only (向量檢索) → （如需要）Orchestrator.ask (傳送 Prompt 給 LLM) → LLM 產生答案 → Service 後處理 (簡體→繁體、組裝來源與時間) → 回傳給使用者。
